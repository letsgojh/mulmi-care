# 공모전 제출물

## 제출 조건 (기획서 01·02장 안내)
- 마감: **2026-11-15(일) 23:59**. 마감 전 같은 발신자의 최종 발송본으로 심사.
- 기획서(접수양식) 제출은 필수. 시연 영상, GitHub 저장소, APK는 **선택, 가산점 있음**. 숏폼 링크는 선택, 가산점 없음(별도 특별상).
- **공유 링크와 첨부자료에 개인정보·계정정보·개발자 실명이 노출되지 않아야 한다.**
- 이메일 발송은 사용자가 직접 한다. Claude는 메일을 보내지 않는다.

## 실명·개인정보 점검 (공개 전 필수)
| 대상 | 확인 |
|---|---|
| 저장소 파일 | `.docx`가 없는가. `git ls-files`에 개인정보가 들어간 파일이 없는가. `grep -rnE "010-[0-9]{4}|@gmail|@naver"` |
| 커밋 이력 | `git log --format='%an <%ae>' \| sort -u`에 실명·개인 이메일이 있는가. 있으면 사용자에게 알리고 처리 방법(새 저장소로 이력 없이 올리기 등)을 함께 정한다. 이력 재작성은 사용자 확인 없이 하지 않는다 |
| GitHub 계정 | 계정 이름이나 프로필에 실명이 보이는가. 사용자에게 확인을 요청한다 |
| APK | 릴리스 서명 키의 인증서 정보(CN, O 등)에 실명이 없는가. `keytool -printcert -jarfile app-release.apk` |
| 스크린샷·영상 | 계정, 알림, 실명이 화면에 보이지 않는가. 음성에 이름이 나오지 않는가 |
| README·문서 | 작성자 실명, 학교, 연락처가 없는가 |

## APK
```bash
./gradlew :core:test :app:assembleRelease
```
- 테스트가 실패하면 APK를 만들지 않는다.
- 서명 키스토어와 비밀번호는 저장소에 넣지 않는다.
- 에뮬레이터에 설치해 SC1~SC6 중 통과한 시나리오를 한 번 더 돌려 본다.

## README 구성
1. 한 줄 소개 (spec 한 줄 소개 그대로)
2. 해결하려는 문제 (짧게, 참고 연구 3편 출처 포함, 의료 효과 주장 없이)
3. 핵심 기능 ①~⑨ 요약과 구현 상태 (구현 / 부분 / 미구현을 사실대로)
4. 구조: core / vehicle / app, 신호 → Effect 흐름 그림
5. 실행 방법: 에뮬레이터 설정, 빌드, 테스트
6. 안전·개인정보 원칙 (S1~S10)
7. 검증 항목 결과와 한계 (`pleos-sdk/references/verification.md`, `docs/emulator-checklist.md` 기준)

구현하지 못한 기능을 구현했다고 쓰지 않는다.

## 시연 영상 대본
`docs/emulator-checklist.md`에서 통과한 시나리오만 쓴다. 장면마다 에뮬레이터 신호 조작(화면 한쪽)과 앱 반응(소리 자막, 공조 값 변화)을 같이 보여 준다. 차량 소리는 영상에서 잘 안 들릴 수 있으니 "왼쪽 소리" 같은 자막을 붙인다.
