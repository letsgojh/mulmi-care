# 멀미케어 요구사항

- 구조화된 명세: [docs/spec.md](../../../docs/spec.md). 모든 규칙에 ID가 있다.
- 기획서 원문: [docs/plan-original.md](../../../docs/plan-original.md). 해석이 갈리면 원문을 따른다.
- 루트의 `.docx`는 개인정보가 있는 원본이다. 읽을 일이 있으면 02장만 보고 다른 곳에 옮기지 않는다.

## 쓰는 법
1. **기능 시작 전**: 해당 F 블록을 읽고, 이번에 구현할 ID 목록을 작업 계획에 적는다.
2. **값이 `TBD`인 경우**: 임의로 확정하지 않는다. `Thresholds`에 기본값을 두고 주석에 spec ID와 "시험 보정 필요"를 남긴다.
3. **기획서에 없는 동작이 필요한 경우**: 구현하기 전에 사용자에게 묻는다. 특히 S 원칙에 닿는 동작(화면, 자동 시작, 차량 제어, 데이터 전송)은 반드시 묻는다.
4. **범위 밖 기능**(F4.7 내비 회전 안내 예고, Gleo AI 연동, 좌석 진동, 박수 인식, 통학 차량)은 1차에서 만들지 않는다.

## 진척 점검
"어디까지 됐어?" 같은 질문을 받으면:
```bash
grep -rhoE '`[FDS][0-9]+(_[0-9]+)? ' core/src/test | sort -u
```
테스트 이름에 들어 있는 ID와 spec.md의 ID를 비교해서, 구현됨 / 테스트 없음 / 범위 밖으로 나눠 보고한다.

## 원문과 spec.md가 다를 때
spec.md는 원문을 요약한 것이므로 틀릴 수 있다. 원문 문장을 인용해 차이를 보이고, spec.md를 고친 뒤 관련 테스트를 확인한다.
