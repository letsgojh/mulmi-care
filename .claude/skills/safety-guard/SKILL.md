# 안전 점검

가능하면 **새 서브에이전트에게 맡긴다.** 구현한 쪽의 판단에 끌리지 않게 하기 위해서다. 서브에이전트에는 이 파일 경로, `docs/spec.md`의 S 표, 점검할 diff 범위만 넘긴다.

## 점검 항목
각 항목에 대해 통과 / 위반 / 확인 불가를 `파일:줄`과 함께 보고한다.

| S | 확인 방법 |
|---|---|
| S1 주행 중 화면 없음 | `ShowScreen`을 내는 모든 core 경로가 정차(P단) 조건을 거치는가. app에서 core를 거치지 않고 Activity를 띄우거나 UI를 보이는 코드(`startActivity`, `setVisible`, 알림 팝업 등)가 있는가 |
| S2 놀이 자동 시작 없음 | `StartBeat`를 내는 경로가 모두 YES 응답 뒤인가. 이를 확인하는 테스트가 있는가 |
| S3 주행 중 조작 요구 없음 | 주행 중 "눌러 주세요", 버튼 확인을 요구하는 멘트나 흐름이 있는가 |
| S4 위험한 제어 없음 | `vehicle/`에서 창문, 도어, 선루프, 주행 관련 제어 API를 쓰는가 (`grep -rniE "window|door|sunroof" vehicle/ app/`) |
| S5 운전자 지적 없음 | TTS 멘트 문자열에 운전을 평가하는 말("천천히", "조심", "급하게", "운전")이 있는가 (`grep -rn "Speak(" core/`와 strings.xml 확인) |
| S6 내비 우선 | 오디오 포커스 처리가 내비 안내 중 비트를 낮추거나 멈추는가. `NaviSpeaking` 중에 `Speak`가 바로 나가지 않는가 |
| S7 아이 개인정보 없음 | 데이터 클래스, DB, 화면에 이름·나이·생일·사진 필드가 있는가 (`grep -rniE "name|age|birth|photo" core/src/main app/src/main` 후 문맥 확인) |
| S8 데이터 외부 전송 없음 | `INTERNET` 권한이 있다면 이유가 있는가. HTTP 클라이언트, 분석·크래시 SDK가 위치나 이동 기록을 보내는가. 기록 보관·삭제 안내 화면이 있는가 |
| S9 의료 효과 주장 없음 | 화면·멘트·README에 "치료", "예방", "효과 입증", "멀미 해결" 같은 표현이 있는가 |
| S10 승인 권한만 | `AndroidManifest.xml`의 권한이 `pleos-sdk/references/permissions.md` 목록과 같은가. SDK 호출 전에 Capability 확인을 하는가 |

## 결과 처리
- 위반이 하나라도 있으면 "커밋/제출 전에 고쳐야 함"으로 보고한다.
- 위반을 고칠 때는 재발을 막는 테스트를 먼저 추가한다(core에서 표현할 수 있는 경우). 예: S1 → 주행 중 신호 시퀀스에서 `ShowScreen`이 없음을 단언.
